# Project governance

The project is maintained by **4alvit (alvit)**. The maintainer reviews proposed
changes, prioritizes issues, maintains repository and CI access, handles private
security reports, and authorizes releases after documented acceptance checks.
Contributors propose changes through public issues and focused pull requests.
Automation runs checks and may assist reviews; it is not a replacement maintainer.

Decisions and their technical reasons belong in the relevant issue or pull
request. Contributors can request reconsideration there with reproducible
evidence. Security details stay in the private reporting process until coordinated
disclosure. Changes require the repository's normal checks and independent review;
branch protection is not bypassed for releases or badges.

There is currently **no backup maintainer or tested mechanism to restore
repository, CI and release access within one week** if the primary maintainer is
unavailable. Public source and automation do not solve this access-continuity gap.
Appointing a willing backup, granting appropriate access and testing recovery are
open organizational work, not completed controls.

See [contributing](CONTRIBUTING.md), [conduct](CODE_OF_CONDUCT.md),
[security](SECURITY.md) and [release responsibilities](RELEASING.md).
